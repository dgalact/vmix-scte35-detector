# vMix SCTE-35 Detector & Ingest Relay

[English](README.md) | **Русский**

Система автоматической врезки рекламы по меткам SCTE-35 и медиа-релей входящего потока для эфирного вещания в vMix.

## Обзор

В профессиональном вещании и интернет-трансляциях приёмному тракту автоматизации требуется отслеживать метки SCTE-35 (cue-out / cue-in) и переключать эфир на локальные рекламные блоки или графические заставки без сбоев в основном видеопотоке и без потери мультиязычных аудиодорожек.

Данный проект предоставляет полностью изолированное, надёжное решение:
- **Медиа-релей (Stream Ingest Relay)**: низколатентный релей в режиме сквозной передачи (raw passthrough), который принимает входящий поток SRT/UDP и раздаёт его локально на vMix и детектор меток.
- **Детектор SCTE-35 (SCTE-35 Detector)**: легковесное приложение на чистом Go, которое в реальном времени разбирает транспортные пакеты MPEG-TS, декодирует команды SCTE-35 (`splice_insert`, `splice_null`, cue-out, cue-in, автовозврат по таймеру) и управляет vMix через локальный HTTP API.
- **Панель оператора (Operator GUI)**: графический интерфейс для мониторинга статуса vMix, выбора входов и визуальной индикации рекламных пауз.

## Архитектура прохождения сигнала

```text
Входящий поток (SRT Caller / UDP)
                 │
                 ▼
     [ START-RELAY.cmd ] (FFmpeg Raw Ingest Relay)
         │
         ├── srt://127.0.0.1:10001 (SRT Listener, Raw TS)
         │       └──▶ vMix (Вход Stream / SRT Caller, "Audio Track: All")
         │
         └── udp://127.0.0.1:10002 (UDP, Raw TS)
                 └──▶ [ vmix-scte35-detector.exe ] (Анализатор на Go)
                             │
                             └──▶ HTTP API (127.0.0.1:8088)
                                     └──▶ CutDirect на рекламный вход / возврат в эфир
```

### Преимущества раздельного Raw Passthrough

1. **Отсутствие перекодирования и джиттера PCR**: В отличие от стандартного демультиплексирования и повторной сборки (`-f mpegts`), релей работает в режиме `-f data -raw_packet_size 1316`. Он пересылает исходные 188-байтные пакеты MPEG-TS байт в байт без пересчёта меток времени PCR/PTS, исключая сбросы буфера SRT и краши декодера vMix.
2. **Полное сохранение аудиодорожек**: Многоязычные аудиодорожки (например, несколько стереопар) передаются без даунмикса и без перекодирования.
3. **Субмиллисекундная задержка**: Локальная передача пакетов на детектор по UDP занимает менее 1 мс, обеспечивая мгновенную реакцию на метки cue-out.
4. **Отказоустойчивость**: Любой перезапуск или сбой детектора никак не влияет на плавность воспроизведения основного эфира в vMix.

## Системные требования

- **Windows 10 / 11** (Intel/AMD `x64` или ARM64 / виртуальная машина Parallels на Apple Silicon).
- **vMix** (с включённым веб-контроллером на стандартном порту `8088`).
- **FFmpeg** для Windows (используется скриптом `START-RELAY.cmd`). В комплект входит скрипт загрузки `Install-FFmpeg.ps1`.

## Быстрый старт

### 1. Подготовка vMix
1. Добавьте новый вход: **Stream / SRT** -> Тип: **SRT (Caller)**, Порт: `10001`, Адрес: `127.0.0.1`.
2. В настройках входа убедитесь, что включены все необходимые звуковые каналы (например, `Audio Track: All`).
3. Создайте или назначьте вход для рекламной подложки/заставки (например, `Blank` или `AD_BREAK`).
4. Убедитесь, что Web Controller включён в **Settings -> Web Controller** (порт `8088`).

### 2. Указание адреса потока
Откройте или создайте файл `stream-url.txt` в корне программы и вставьте адрес источника:
```text
srt://your-stream-server.com:9001?mode=caller&transtype=live&latency=2000000&pkt_size=1316
```
*(Также можно указать просто `IP:PORT` или домен — скрипт запуска автоматически добавит необходимые параметры SRT).*

### 3. Запуск релея
Запустите `START-RELAY.cmd`. Откроется окно консоли, начнётся прием потока и откроется порт `127.0.0.1:10001` для vMix.

### 4. Запуск графической панели детектора
Запустите `START-GUI.cmd`.
- Проверьте основной вход (**Main Input**, например `1`) и рекламный вход (**Ad Input**, например `Blank`).
- Нажмите **Запустить автоматизацию**.
- Панель отобразит текущий статус vMix и покажет индикатор `ИДЕТ РЕКЛАМА` при срабатывании рекламной паузы.

## Логика безопасности

- **Проверка активного входа**: Переключение на рекламу по cue-out происходит только в том случае, если в этот момент в Program активен именно основной вход.
- **Приоритет ручного управления**: Если оператор вручную переключил вход в vMix во время рекламы, автоматический возврат отменяется, чтобы не перебивать действия режиссёра.
- **Аварийный возврат по таймеру**: Если входящая метка cue-in потерялась в сети или была повреждена, детектор автоматически возвращает основной эфир по истечении заявленной длительности рекламного блока.
- **Дедупликация меток**: Повторные пакеты с одинаковым Event ID отфильтровываются и не вызывают ложных срабатываний.

## Сборка из исходников

Детектор написан на чистом Go и использует только стандартную библиотеку (без внешних зависимостей):

```bash
# Запуск тестов
go test -v ./...

# Сборка для 64-битной Windows (x64)
GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/windows-amd64/vmix-scte35-detector.exe .

# Сборка для ARM64 Windows (Parallels на Apple Silicon)
GOOS=windows GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o dist/windows-arm64/vmix-scte35-detector.exe .
```
